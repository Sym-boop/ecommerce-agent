## 一、议题与结论

### 1. 项目范围确认

确认项目为「多 Agent 电商全流程智能运营与决策系统」，按 `项目(1).docx` 划分六大模块：MCP 适配器、向量知识库、Supervisor 主控、文案生成器、定价监控、运营驾驶舱。详细功能以 `docs/requirements.md`（C 起草）为准，验收标准按功能编号（VEC/CPY/SUP/DSH/APR 等）逐条对照。

### 2. 分工确认

| 成员 | 模块 | 交付 |
|---|---|---|
| A | MCP 适配器 | `mcp_servers/`（ERP、千川/Meta 广告） |
| B | 向量知识库 | Milvus 封装、知识导入脚本、10 万条语料 |
| C | Supervisor 调度 | LangGraph 工作流 + 需求文档维护 |
| D | 文案生成器 | 三平台风格 + 违禁词过滤 |
| E | 定价与竞品监控 | 调价建议 + 阈值熔断 |
| F | 前端驾驶舱 + 文档 | `frontend/` 全部、readme.md、claude.md、会议纪要、`data/samples/` 压测样本 |

### 3. 技术决策

- 编排框架采用 **LangGraph**，Supervisor 节点 + 条件边 + 反思纠错环路。
- 向量库采用 **Milvus 2.4 standalone**（docker-compose 起 etcd + MinIO）。
- 消息队列 **Redis + Celery**，文案批量生成走 Worker。
- 外部系统统一 **FastMCP** 封装为可自省微服务。
- 前端 **Vue 3 + Element Plus + Pinia**，WebSocket 推送节点状态与审批事件。
- **人机协同熔断**：广告预算 ≥ 50000、调价幅度 > ±10%、文案重大发布三类操作必须人工审批，前端 WebSocket 阻断提醒。

### 4. 接口契约与端口约定

- 后端 FastAPI 端口 **8000**，REST 前缀 `/api/v1`，WebSocket `/ws/dashboard`。
- 统一响应体 `{code, msg, data}`。
- 中间件端口：Milvus 19530、Redis 16379（宿主机映射）。
- 前端开发端口 5173，Vite 代理 `/api` → 8000。
